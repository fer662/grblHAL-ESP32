# Thread cycle — 0.3.26

Uses the native grblHAL planner and synchronized stepper, with phase acquisition before X entry:

1. Retract X to the configured 0.5 mm clearance.
2. Return Z to the starting bound, then take up one Z step inside it.
3. Queue the X plunge and synchronized Z cut together. Wait for the calculated
   spindle phase with X still at clearance and Z stationary.
4. Plunge X to depth, stop X, and hand off directly to the Z-only synchronized
   block. There is no second index wait or foreground command gap at depth.
   X stays at cutting depth throughout Z travel.
5. After Z stops, retract X to clearance and return Z for the next pass/start.

For entered Z 0..10 mm, the default 200 Z steps/mm gives approach Z 0.005 and
finish Z 10: **9.995 mm of Z travel at cutting depth**. Reverse travel runs from
9.995 to 0. The preview displays these commanded endpoints and length, first/final
X depth, and retract target in native work coordinates and the selected units.
There is no moving-entry deduction, estimated usable-thread region, or inferred
stock-contact surface.

The native planner retains speed and acceleration limits. Z accelerates and
brakes with X engaged. There is no preview RPM window or acceleration-distance
acceptance test. Geometry must fit at least the takeup step and one cutting step.
The cut waits armed if its requested lead times RPM exceeds the actual axis maximum;
there is no additional 10% rate headroom. The sequence
matches old H5, while pulse timing and acceleration remain grblHAL-controlled.
Multi-start lead/phase, depth progression, internal/external direction, bounds,
G54, cancellation and Rapids are retained. X maximum speed remains 5 mm/s;
0.3.25 restores X acceleration from the 500 mm/s² trial to 25 mm/s². This slows
X plunge/retract acceleration with Z stationary; it does not subtract Z cutting travel.

The internal `$P4THREADENTRY` command submits two native planner blocks, validating
both soft-limit targets before queuing either. The opt-in `SPINDLE_SYNC_PRELOAD`
core support gates the first block on spindle phase, forces zero junction speed
between X and Z, and keeps the driver's pre-established Z phase origin. Every
STEP pulse and acceleration profile is generated by grblHAL. Ordinary G33 is
unchanged and is still used to resume a cut that stopped partway along Z.
Continuous-block synchronization and the old moving-entry geometry remain disabled.

The entry phase uses the native rounded X distance, rate and acceleration to
calculate the rest-to-rest plunge duration, plus Z's acceleration phase offset.
It advances the acquisition phase by that duration's spindle rotation. This is
scheduled motion, not contact sensing: the tool still cuts radially while X is
plunging, and physical compliance or spindle-speed changes during the plunge can
affect arrival phase. The existing Z phase controller corrects tracking error;
there is no claim of zero mechanical delay or perfect pitch during Z acceleration.

## Stopped spindle and reversal

RUN may position with the spindle off; Thread now waits with X clear before plunging.
Index acquisition has no five-second timeout in the P4 build. Spindle stop during
a cut retains depth/pass/start after native deceleration. Restart reacquires
phase from the stopped Z coordinate without replaying X infeed. Reverse rotation
retraces toward the original approach; it does not complete or advance the pass.
A spindle stop/reversal during acquisition or the X plunge instead resets that
entry, retracts to clearance and re-arms the same pass; it must calculate a new
entry phase before plunging again. Explicit STOP does not automatically retract.
At the approach it waits for forward rotation. Explicit STOP cancels and cannot
automatically resume. The external switch still physically controls the spindle.

## Verification

`thread_entry_native_test.py` executes production queueing, driver phase setup,
core index-wait code, native planner, segment generator and step ISR on a virtual
clock. It covers all five depths at 50–500 RPM, 1–29 RPM, both X/Z travel directions,
multiple phases/starts, triangular/trapezoidal entries, X acceleration 10/25/500,
small +/-5 RPM/s changes, soft-limit rejection, and cancellation while waiting,
plunging and cutting. It asserts exact X/Z step counts/endpoints, zero X motion
through the Z cut, a single clear-tool index wait, and a bounded handoff delay.

At normal 25 mm/s² X acceleration and steady 50–500 RPM, simulated last-X-pulse to
first-Z-pulse gaps are about 5–11 ms. A first physical Z step naturally takes longer
at hand-turn speed. The suite's maximum phase displacement at the Z block start
is below 0.020 mm; steady-region phase error is below 0.010 mm. These are simulation
results with the configured step resolution, not measurements of the loaded lathe.

Cycle lifecycle tests cover stopped startup, interrupted-entry recovery, repeated
passes (including stale phase latches), STOP and mid-cut resume/reversal. Existing
single-block native G33 regression tests continue to cover resumed cuts. Hardware
index/task latency, actual torque and physical stock contact still need an on-lathe
check after installation.
